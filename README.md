# AidPath

A working, independently built student-support navigator for UC Berkeley. It turns structured needs into source-backed, explainable next steps, never an eligibility approval.

## What is implemented

- React + TypeScript responsive student experience: adaptive questions, ranked recommendations, evidence, official sources, directory, saved checklists, print, feedback, session deletion.
- 15 resource profiles backed by 12 retrieved official source pages; four profiles are pathways of one emergency fund, not separate awards. Source snapshots and SHA-256 fingerprints are committed.
- Deterministic rule engine with all ten operators requested in the brief, tri-state evidence, fail-closed provenance/freshness checks, configurable ranking weights.
- Server API with persistent D1 storage, immutable policy-version payloads, anonymous per-browser sessions, validated actions, same-origin POST protection, structured error logging and error records.
- Source-change checker, explicit human approval endpoint, 30-day cleanup, migrations, Node unit/integration tests, Hypothesis property tests, Playwright end-to-end specification, CI, evaluation and privacy documentation.

## Stack decision

The brief explicitly permits changing architecture with justification. This version uses **React / Vinext (Next-compatible routing), TypeScript, and Cloudflare D1 (SQLite)** so the frontend, API, and persistent database can run together in the available hosting environment. It does **not** claim to use FastAPI or PostgreSQL. There is one production policy engine, avoiding divergent Python and TypeScript eligibility logic. Python drives Hypothesis tests against that engine.

## Local setup

Node 24+ and Python 3.11+ recommended.

```sh
npm install -g pnpm
pnpm install --frozen-lockfile
pnpm exec drizzle-kit generate
pnpm run build
# See docs/OPERATIONS.md for local D1 setup and preview instructions.
```

The source uses the provided Sites runtime build integration. Hosted configuration is `.openai/hosting.json`; database binding is `DB`. Production migrations are generated by Drizzle and applied by the hosting platform. Do not modify applied migrations.

## API

`GET /api/aidpath` starts/resumes an anonymous cookie session and returns typed questionnaire state, directory, recommendations and saved plan. `POST /api/aidpath` accepts actions `select_need`, `answer`, `restart`, `back`, `save`, `check`, `remove`, `event`, `feedback`, `delete`. It rejects out-of-order questions and invalid enum values. `POST /api/maintenance` requires a deployment secret and performs source checks and cleanup; `POST /api/policy-review` approves only the exact bundled fingerprint after explicit human review. See docs/API.md.

## Project status and limitations

A functioning software implementation is not a completed ten-week research internship. Discovery interviews, 20–50 participant study, independent policy approval, and production-scale benchmarking are outstanding. No participant results or resume impact claims were fabricated. Initial rules are AI-assisted interpretations. Source availability is checked separately from correctness of interpretation. The app labels this explicitly and remains a private project.

The directory contains 15 profiles, including shared-fund pathways and advisory services. It does not cover all university support. No documents, financial amounts, student IDs or diagnoses are collected. Background maintenance has code and a schedulable workflow; an operator must configure its secret and scheduler before public release. Freshness expires after 30 days even without that scheduler. There is no external monitoring vendor configured; errors are captured in structured logs and a retention-limited database table.

## Language and personal reminders

The EN/Español control translates navigation, all questionnaire prompts and answers, source-derived summaries and steps, and action-plan controls. Official program names and external source pages remain unchanged. Only the language preference is stored in localStorage; switching language does not change rule values or restart intake.

Saved plan entries support an optional future follow-up date and time. The date persists with the anonymous plan. Add to calendar downloads an RFC 5545 calendar event with a display alarm at the chosen time; import it and enable alerts in a calendar app. AidPath itself does not send email or push alerts. These dates are user-selected reminders, not verified program deadlines. Imported events are independent: edits or deletion in AidPath do not update the calendar. Plan retention remains 30 days; imported calendar events remain under the calendar provider's control.
